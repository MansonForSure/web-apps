Chess between two devices. No game server.

Every move travels straight from one browser to the other. Choose how the two devices first find each other.

Option A · easiest

Online link

Share a link or a 6-letter code. The free public PeerJS service only introduces the devices; the game itself runs device to device. Works anywhere with internet.

Option B · zero server

Swap QR codes

Put the devices side by side and scan two QR codes. No signaling server is involved; the devices only ask Google’s public STUN server for their own address.

How does this work?
  1. Pairing (“signaling”). Browsers cannot listen for incoming connections, so the two devices first swap a short description of how to reach each other. Option A sends it through PeerJS’s public server; Option B has you carry it across yourself as two QR codes.
  2. Direct connection. WebRTC then opens an encrypted data channel straight between the devices. If a strict network blocks direct connections, Option A can fall back to PeerJS’s public TURN relay; Option B cannot.
  3. Playing. Each move is a tiny message such as {"uci":"e2e4"}. Both devices check it with the same chess rules. GitHub Pages only serves these static files.
